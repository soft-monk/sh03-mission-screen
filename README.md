# FastHTML · 场景一播片

一个**不依赖任何框架、不打包、不联网**的播片播放器。双击 `index.html` 就能放，总长 **04:35**，18 屏。

## 1. 怎么打开

双击 **`启动演示-平面.bat`**（默认，平面版）或 **`启动演示-3D地形.bat`**（真 3D 地形版），会自动起本地服务并打开浏览器。不能直接双击 index.html。
也可以直接跳时间：`index.html?t=95`（跳到第 95 秒），`index.html?t=95&pause=1`（停在那一帧）。

**快捷键**：空格 暂停/继续 · ← → 切屏 · Shift+← → 切章 · R 重播 · F 全屏 · H 隐藏操作层

## 3. 改一屏（最常见）

以 SH-03 为例，只改 `scenes/s03-situation.js` 里的 `render(t, e)`。
**`t` 是这一屏内部的秒数（从 0 开始）**，比如「第 3 秒开始淡入、用 0.8 秒淡完」：

```js
n.style.opacity = FX.at(t, 3.0, 3.8);            // 0 -> 1
n.style.transform = "translateY(" + (1 - FX.easeOut(FX.at(t, 3.0, 3.8))) * 20 + "px)";
```

存盘 -> 浏览器按 F5 -> 立刻看到。**没有编译，没有打包，1 秒内。**

> 关键约定：`render(t)` 必须是**纯函数**——同一个 `t` 永远画出同一个画面。
> 不要在里面写「+=」「上一帧」这类状态，否则拖进度条/重播会乱。这也正是它能随便跳时间的原因。

## 4. 加一屏 / 换一屏

1. 复制 `scenes/placeholder.js` 成 `scenes/s09-recon.js`，改 `window.SCENES["SH-09"] = { build, render }`；
2. `index.html` 里加一行 `<script src="scenes/s09-recon.js"></script>`（放在 placeholder.js 之前）；
3. 刷新。时间轴不用动，SH-09 会自动换成新版（`js/timeline.js` 里那 20 秒就是它的）。

> 屏的 id 必须和 `js/timeline.js` 里的 `id` 一致；没写 scene 的屏自动落到占位模板。

## 5. 改排片

全在 `js/timeline.js`：

- 改某屏时长：改下一屏的 `t`（程序按下一个 `t` 自动算出上一屏时长）；
- 改字幕：`subs` 数组，`t` = 从播片起点算的秒数；
- 改阶段：`chapters` 数组（进度条 5 段按这里切）。

改完检查一下：**总长 = 最后一屏的 t + 它的 dur**，且 `chapters` 的时间要和 `phases` 对齐。

## 6. 换地图区域

1. 在 `_tools/gen-data.mjs` 顶部改 `z / X0 / Y0 / COLS / ROWS`（瓦片来自 `map-2d/tiles/raster/<z>/<x>/<y>.jpg`）；
2. `node _tools/gen-data.mjs` —— 会重新拷贝瓦片、重算 `js/map-meta.js`、重新导出 `data/scenario.js`。

底图是 Web 墨卡托，所以 `js/geo.js` 的投影和任何地图软件一致，坐标可以直接用经纬度。

## 8. 已知边界

- 地图是**静态瓦片 + 相机变换**，不能拖动/缩放交互（播片不需要）。要交互再换真地图引擎。
- 无人机走的是**脚本航线**（贝塞尔插值），不是真仿真：没有避障、风阻、电量。
- 没有配音，只有字幕。要配音就在 `subs` 上加 `audio` 字段，播放到点播一下即可。

## 9. 调试与自检

- 地址栏加 `?t=秒数` 直接跳到某一秒，例如 `index.html?t=24`；再加 `&pause=1` 停在那一帧。
- 出问题时页面顶部会出现红色错误条（只显示最近 4 条唯一错误），复制给我即可。
- `node _tools/verify.mjs` 跑静态自检（引用完整性 / 语法 / 瓦片 / 时间轴 / 字符污染）。
- `node _tools/gen-data.mjs` 重新导出瓦片与场景数据（换了地图区域才需要跑）。

## 10. 已知实现细节

- 播放时钟有**双驱动**：`requestAnimationFrame` + 60ms `setInterval` 看门狗。浏览器把 rAF 挂起（失焦、省电、无头）时照样走，两者共用同一个 `last` 时间戳，不会重复计时。
- 单屏渲染出错**不会中断播放**：异常被捕获后进错误条，下一帧继续。
- 时间戳做了反向钳制（`Math.max(0, now - last)`），避免两种时钟源互相倒流。

## 11. 等待点（播片中途停下来等人点）

`js/timeline.js` 里有个 `holds` 数组：

```js
const holds = [{ t: 25.5, screen: "SH-03", prompt: "请选择任务场景" }];
```

播到 `t` 就自动暂停，不再往下走，直到有人点了屏里的按钮（由各屏自己处理点击，
点完调 `PLAYER.seek(下一屏起点)` + `PLAYER.play()` 继续）。
不点就一直停着；想强制跳过按 `→` 切下一屏。

目前只有 SH-03「场景选择」用了这个机制。后面 SH-05 方案确认、SH-14 打击确认
这种需要人做决定的地方，加一行配置就行。

## 14. 两个版本（平面 / 3D 地形）

同一套代码、两个启动脚本，靠 URL 参数 `?mode=` 区分，服务端只跑一份：

| 脚本 | URL | 地图 |
|---|---|---|
| `启动演示-平面.bat`（默认） | `?mode=flat` | 只建卫星栅格层，**style 里根本没有 DEM 源**，一张地形瓦片都不会请求；相机 `pitch 55° / bearing -20°`，斜着看的平整卫星图 |
| `启动演示-3D地形.bat` | `?mode=3d` | 额外加载 raster-dem，地形拉伸 3 倍；相机 `pitch 62°→70°` |

- 平面模式为什么能斜着看：`pitch` 只是**相机倾斜**，和地形拉伸是两件事。
- 3D 的代码一行没删（`mapview.js` 里 `?mode=3d` 分支），随时双击另一个 bat 对比。
- 平面模式不加载 DEM，省掉整套地形渲染管线（初始化更快、显存更省）。
- 两个 bat 可以先后双击：服务已经在跑时，第二个只是换模式开浏览器，不会冲突。

## 15. 性能口径（对齐 webmap-app / map-2d）

参考实现是 `D:\dsh_workpath\webMap\map-2d`（mission-app 用的地图模块）。它的三条关键前提，我们已经对上：

1. **画布 = 屏幕实际设备像素**
   `mapview.js` 用 `舞台缩放 × devicePixelRatio` 调 `map.setPixelRatio()`，并封顶 1（`?px=2` 可放开）。
   以前 MapLibre 默认按 `devicePixelRatio` 渲染 1920×1080 画布 —— 在 2 倍屏上是 3840×2160 =
   **830 万像素/帧**，比实际显示多 4 倍。这是"连 2D 都卡"的头号原因。
2. **镜头每帧跟随**
   平面版去掉 0.12 秒节流（原来相当于 8fps 的镜头，看着一格一格跳），改成每帧 `setView`；
   3D 版仍保留节流（每次跳相机都要重建地形网格，贵）。
   线程无关：`render(t)` 依然是纯函数，拖进度条照样能精确对位。
3. **不做每帧重绘的 DOM 特效**
   等待点的卡片/提示条"呼吸"从「每帧改 box-shadow」改成「CSS 静态阴影 + transform 缩放」
   —— 后者只走合成层，不触发重绘。

**仍然有意保留的差异**：平面版 `pitch 55°`（参考实现是 `maxPitch: 0` 纯正俯视）。
倾斜会让可视瓦片数成倍增加；如果还觉得卡，把 `s03-situation.js` 里平面分支的 `55` 改成 `25 ~ 35` 即可。

## 19. 地图只建一次（整片共享）

以前每屏都 `new` 一个 MapLibre：SH-03 一个、SH-04 又一个 —— 切屏时瓦片要重走、相机要从初始机位重来、图元和标签重新叠一遍。

现在改成**单例**（`js/mapview.js` 里的 `MapViewShared`）：

- 整片只创建一个 MapLibre 实例，就是 SH-01/02 期间预热时建好的那一个；
- 后面每一屏要地图，只是把**同一个 canvas 元素搬进自己的容器**（`appendChild` 挪位置），WebGL 上下文不丢；
- 相机位姿、已加载瓦片、已画好的区域图元**原样延续**；标签按文字去重（`labelCache`），不会出重影；
- 搬完调一次 `repaint()`（`resize` + `triggerRedraw`）校准尺寸。

两个配套约束（踩过坑，别再改回去）：

1. **不能从"正在显示"的那一屏手里抢画布**：`MapViewShared` 会检查当前父节点所在 `.scr` 是否有 `.on`，有就不挪（预热屏是隐藏的 `.pre`，抢不走）。
2. **预热不再调 `render(0)`**：那会把共享地图上的区域透明度按 t=0 重置成 0，导致当前屏的图元集体消失；同时如果当前屏已经在用地图（`usesMap: true`），预热直接跳过。

## 26. SH-06：A* 航路（离线算好，运行时不计算）

**算法**

| 项 | 值 |
|---|---|
| 网格 | 200 m |
| 起终点 | 起：我方集结区边缘 4 个出口（互相 1.6 km）；终：任务区东边内侧 4 个落点（南北间隔 4.4 km） |

### 26.1 航路算法 v2（改为样条走廊）

v1 用 200m 栅格 A*，结果很差：起点绕一圈、进任务区还要扭一下 —— 因为"栅格寻路 + 硬性 1km 间隔"会互相打架。

v2 改成**控制点 + Catmull-Rom 样条**：

| 步骤 | 做法 |
|---|---|
| 控制点 | 每条 5 个手写点：起点在集结区朝任务区的一侧，中途分带绕禁飞区，终点落任务区东边界 |
| 平滑 | Catmull-Rom 插值 → 按 250m 重采样（每条约 100 点） |
| 分带 | 编组1/2 从禁飞区**北侧**过（离 7.5km / 5.6km），编组3/4 从**南侧**过（1.9km / 3.8km） |
| 校验 | 脚本强制检查：离禁飞区 ≥1000m、任意两条最小间距 ≥1000m，不通过就不写文件 |
| 输出 | `data/routes.js`，运行时不计算 |

**实测**

| 编组 | 航点数 | 长度 | 离禁飞区 |
|---|---|---|---|
| 编组1 光电 | 113 | 37.6 km | 7492 m |
| 编组2 雷达 | 101 | 35.7 km | 5589 m |
| 编组3 电子 | 93 | 33.9 km | 1943 m |
| 编组4 通信 | 93 | 32.5 km | 3782 m |

任意两条间距 ≥1000 m ✓；起点直奔西北、无回绕；进任务区为平滑曲线、无折返。
