# 通用需求 · 播放演示

> **这份文档是什么**：整个播片演示的**通用需求与设计口径**，分两部分：
> - **第一部分**：SH-01 ~ SH-05（三场景共用）——时间轴、界面与文字、交互、**地图生命周期**、AI 与语音、工程约定；
> - **第二部分**：SH-06（场景一）——任务区航路、飞行仿真、扫描与覆盖。
>
> **不记录**某一次改动的过程（那是 `HANDOFF.md` 的事），也不写逐帧视觉细节（那是源码注释的事）。
> 写之前逐条回源码核对（`js/timeline.js`、`data/flows.js`、`scenes/s03-situation.js`、`js/main.js`、`js/mapview.js`、`data/scenarios.js`），**不照抄** `docs/timeline-*.md`（那几份已有过期内容）。
>
> 优先级：`AGENTS.md`（工作规则）> `PROJECT_MAP.md`（结构与技术约束）> 本文档（设计口径）> `HANDOFF.md`。

## D. 地图生命周期（重点）

**一句话**：*SH-03 是纯静态底图、不建图；在 SH-03 选完场景之后才决定有没有地图；一旦有图，SH-04 → SH-05 → SH-06 全程继承同一个实例，切屏只搬容器、不重建。*

| 编号 | 规则 | 依据 |
|---|---|---|
| M1 | **全片只有一个 MapLibre 实例**，由 `MapViewShared(host)` 复用；任何屏都不得 `new maplibregl.Map`。 | `js/mapview.js` |
| M2 | **SH-03 不建图**：DOM 里只有 `.s3-map-static`（静态底图 `assets/img/basemap.jpg` + 暗角），没有 `.s3-map` → `mapHost` 为空 → `NEED_MAP = false`，不建实例、不请求瓦片。 | `s03-situation.js:426/447/449` |
| M3 | **选完场景才建图**（25.5 s 等待点之后）：<br>• **场景二**：在 620 ms 过渡期间用屏幕外 `#mapwarm` 容器**预热建图**，SH-04 首帧即有图；<br>• **场景一**：**不预热**，进入 SH-04 的 `build()` 时才建图（首帧可能短暂空白）；<br>• **场景三**：`mapBounds = null` → `NEED_MAP = false`，全程不建图，地图区显示「地图数据待接入」。 | `s03-situation.js:1593-1602`、`449-451` |
| M4 | **SH-04 → SH-05 → SH-06 继承同一个实例**：每屏有自己的 `.s3-map` 容器，切屏时 `onShow` 调 `MapViewShared(e.host)` 把 canvas 搬到新容器，**不重建**。 | `s03-situation.js:2140` |
| M5 | 只有**重播**才 `MapViewReset()` 销毁重建；正常切屏、回看都不重建。 | `js/main.js:229` |
| M6 | 相机 / 边界 / 缩放范围按场景配置生效：`cfg.camera`、`cfg.mapBounds`、`cfg.minZoom`；`maxZoom` 固定 12。 | `MapViewSetBounds` / `MapViewSetZoomRange` |
| M7 | **区域图元按屏重画、离开即清**：任务区/集结区/禁飞区/标签在每屏 `build()` 重画，`onHide` 调 `clearAreaGraphics` 清掉；共享实例上不得残留上一屏的业务图元。 | `s03-situation.js:2123/2158` |

| 编号 | 条件 |
|---|---|

| A6 | **雷达 SAR：6 架**，南北向平行腿**蛇形**（每架 3~4 条腿），腿距由西 2.4 km 收到东 1.6 km。 |
| A7 | **雷达 GMTI：2 架**，同一条**东西向跑道环**（直边平行上下边、两端半圆），两架半圈错开。 |
| A8 | **电子干扰：2 架**，同一条**南北长轴跑道环**，两架半圈错开。 |
| A9 | **通信：4 架**，任务区中心的**中继环** 2 架 + 集结区方向的**走廊环** 2 架，各半圈错开。 |

1. **SAR 覆盖约 75%**：侧视只扫一侧，覆盖率天然只有一半多，属于物理设定。
