# FastHTML 演示工程概述

> 这份文档讲**它是做什么的、为什么这样做**。具体目录结构、怎么改某一屏、瓦片怎么补，见同目录的技术文档 `README.md`。

---

## 它是什么

一套**离线运行、双击即放**的指挥流程演示。

它把一段作战流程拆成若干"分镜"，用一条时间轴从头串到尾：态势铺开、AI 研判、兵力编组、链路构建、侦察展开、目标确认、打击执行、效果评估、任务收尾。播放时像看一段成片，暂停后又能随时拖到任意时刻、回看任意一帧。

它不是业务系统，是一段**可以点、可以拖、可以停下来讲的动态分镜**。

## 为什么这么做

**汇报时不用等系统。** 演示不依赖后端、不依赖网络、不依赖数据库，双击启动文件、打开浏览器就能放。现场出问题，最坏情况换台机器也一样放。

**改一版当场就能看到。** 从一句话文案到一个区域的坐标，改的都是配置；不需要编译、不需要装依赖、不需要等待热更新。改完刷新即生效。

**画面可复现。** 每一帧都只由"当前时间"决定。同一时刻，无论是自动播放、暂停、拖动进度还是重播，看到的画面完全一致。这让反复对齐细节成为可能——你说"第某处那块面板挡住地图了"，下一次一定还是那一帧、那个位置。

## 给谁看

| 场景 | 用法 |
|---|---|
| **汇报 / 评审** | 当成品放，按节奏讲；需要展开时暂停，指着画面说 |
| **需求对齐** | 边聊边改，改完立刻放一遍，减少"我说的不是这个意思" |
| **开发自测** | 任意跳秒、拖拽、重播，验证某一帧的布局与状态 |

## 演的是什么

它演的是一段**完整的作战流程叙事**：从任务下达，到机器给出判断与建议，到人做确认，到兵力按建议展开，到侦察发现目标，到打击与评估，最后收束。

叙事之上是一套**可复用的舞台**：统一的外壳、统一的面板语言、统一的地图与图层体系、统一的时间轴机制。换一条故事线，换的是分镜内容，不是这套骨架。

> 当前先落地一条完整故事线；其余场景沿用同一套外壳，内容另行定义。

## 设计原则

**离线可用。** 底图、脚本库、字体图标全部本地化，运行时不访问外网。

**零构建零依赖。** 没有打包、没有 npm、没有编译步骤。写的就是浏览器直接能跑的东西，避免"换个环境就跑不起来"。

**固定舞台，等比缩放。** 所有画面按同一张画布排版，再整体缩放到实际窗口。布局只在一处定义，不受分辨率影响，也不会在别人机器上错位。

**时间轴即唯一真相。** 画面是时间轴位置的函数，不是一串"播到这儿就触发那个"的回调。因此暂停、拖动、重播、跳转都不会让状态错乱。

**能不看代码就改。** 文案、坐标、时长、顺序这类内容都在配置里，改内容不必碰逻辑。

**先平面，后其它。** 主流程只做平面态势；三维另作独立分支，互不牵连。

## 能力范围

- **地图**：本地瓦片底图，支持多级缩放与兜底底图，相机可复位；区域、标注、航路、图层可叠加。
- **航路**：规划在离线完成、结果固化成数据，演示时只负责呈现，运行时不计算。
- **编队飞行演示**：按真实速度推进的仿真，支持倍速与进度拖拽；轨迹保留历史，可随时回看。
- **界面外壳**：统一的顶栏、侧边菜单、工具条、状态栏与各类面板，新分镜直接复用。
- **播放控制**：自动播放、暂停、跳转、按章节定位；个别分镜可以接管自己的时间轴。

## 明确不做

- **不做真实飞控**：飞行只是"看起来像"的演示，不对接任何真实平台。
- **不接后端与实时数据**：所有内容是预置的、可复现的。
- **不做三维主流程**：三维是独立分支，不影响平面演示。
- **不做移动端适配**：目标就是大屏与桌面浏览器。
- **不做权限、账号、多用户**：它不是系统，是演示。

## 怎么改

| 想改什么 | 改哪儿 |
|---|---|
| 某一句文案、某个数字 | 分镜脚本里的对应字段 |
| 某一屏的时间、顺序 | 时间轴配置 |
| 地图上的区域、标注、航路 | 区域配置或离线规划结果 |
| 整体版式、配色、面板样式 | 该分镜的样式段 |
| 换一条故事线 | 复用外壳，替换分镜内容 |

原则只有一条：**改内容不改机制，改机制先想清楚会不会破坏"同一时刻同一画面"。**

## 现状与边界

一条故事线已成型并持续打磨，其余场景按同一骨架扩展。

需要留意的是：这套东西擅长**把已经想清楚的东西讲清楚**，不擅长替代真实系统做验证。它是一面镜子，不是一台发动机——镜子擦得再亮，也照不出没画上去的东西。
